# 개발요청서 — 매수여력 판정 기능

작성일: 2026-09-07
버전: v1.0
대상: 구현 담당

> 접수 기록: 2026-09-07. 발주자로부터 받은 원문을 그대로 보관한다.
> 착수 지시 전까지 구현하지 않는다.

---

## 1. 목적

보유 주택 매도 대금과 보유 현금을 근거로, 현행 대출 규제 아래에서 매수 가능한 주택 가격 상한을 산출한다.

핵심은 **대출 한도가 매수가 구간에 따라 계단식으로 바뀌는 구조**를 정확히 반영하는 것이다. 단순 역산으로 풀면 틀린 답이 나온다. 상세는 5.4항.

---

## 2. 범위

### 포함
- 매도 시 양도소득세 산출 (1세대 1주택, 재건축 조합원 취득)
- 매도 순현금 산출
- 매수 가능가 상한 산출
- 추가 자금 투입 시 민감도 표시

### 제외 (이번 범위 아님)
- DSR 한도 검증
- 취득세 중과 판정 (일시적 2주택 등)
- 증여세
- 복수 물건 비교
- 스크리너 시세 자동 연동

제외 항목은 구현하지 않는다. 화면에 자리만 잡아두는 것도 하지 않는다.

---

## 3. 입력

모든 입력은 사용자가 직접 넣는다. **비어 있는 값을 0이나 기본값으로 대체하지 않는다.** 필수 입력이 비면 계산을 수행하지 않고, 어느 항목이 비었는지 화면에 표시한다.

### 3.1 매도 대상

| 필드 | 형 | 필수 | 설명 |
|---|---|---|---|
| `sale_price` | 정수(원) | 예 | 매도 예상가 |
| `acq_price_prior` | 정수(원) | 예 | 종전주택 취득가액 |
| `right_value` | 정수(원) | 예 | 권리가액 (종전자산 평가액) |
| `contribution` | 정수(원) | 예 | 부담금 (청산금 납부액) |
| `member_supply_price` | 정수(원) | 예 | 조합원 분양가 |
| `necessary_expense` | 정수(원) | 아니오 | 필요경비. 비면 0이 아니라 "미입력"으로 표기하고 0으로 계산하되 결과에 미반영 사실을 명시 |
| `mortgage_balance` | 정수(원) | 예 | 상환할 주담대 잔액 |
| `hold_rate_prior` | 소수 | 예 | 기존건물분 장특공 보유공제율 |
| `live_rate_prior` | 소수 | 예 | 기존건물분 장특공 거주공제율 |
| `hold_rate_contrib` | 소수 | 예 | 청산금분 장특공 보유공제율 |
| `live_rate_contrib` | 소수 | 예 | 청산금분 장특공 거주공제율 |

장특공 공제율은 이번 단계에서 **직접 입력**으로 받는다. 날짜로부터 자동 산출하는 기능은 넣지 않는다. 재건축 조합원의 보유·거주기간 기산 규칙이 확정되지 않았고, 잘못 자동화하면 틀린 값이 조용히 흘러간다.

### 3.2 매수 조건

| 필드 | 형 | 필수 | 설명 |
|---|---|---|---|
| `cash_on_hand` | 정수(원) | 예 | 보유 현금 |
| `extra_fund` | 정수(원) | 예 | 추가 여유자금. 0 허용 |
| `area_over_85` | 불리언 | 예 | 매수 대상 전용면적 85㎡ 초과 여부 |
| `price_basis` | 열거 | 예 | 대출 한도 구간 판정 기준. `실거래가` / `KB시세` / `감정가` 중 선택 |

`price_basis`는 미확정 항목이다. 12항 참조.

## 4. 규정 파라미터

**아래 값을 코드에 직접 쓰지 않는다.** 별도 설정 테이블 또는 설정 파일로 분리하고, 각 항목에 시행일과 출처를 함께 보관한다. 세제와 대출 규제는 자주 바뀐다.

### 4.1 양도소득세율 (2026년 기준)

| 과세표준 하한 | 과세표준 상한 | 세율 | 누진공제 |
|---|---|---|---|
| 0 | 14,000,000 | 6% | 0 |
| 14,000,000 | 50,000,000 | 15% | 1,260,000 |
| 50,000,000 | 88,000,000 | 24% | 5,760,000 |
| 88,000,000 | 150,000,000 | 35% | 15,440,000 |
| 150,000,000 | 300,000,000 | 38% | 19,940,000 |
| 300,000,000 | 500,000,000 | 40% | 25,940,000 |
| 500,000,000 | 1,000,000,000 | 42% | 35,940,000 |
| 1,000,000,000 | 없음 | 45% | 65,940,000 |

- 지방소득세: 산출세액의 10%
- 양도소득 기본공제: 2,500,000원 (연 1회)
- 1세대 1주택 비과세 기준금액: 1,200,000,000원

### 4.2 대출 한도 (규제지역, 2025-10-15 대책)

| 주택가격 하한 | 주택가격 상한 | 대출 한도 |
|---|---|---|
| 0 | 1,500,000,000 | 600,000,000 |
| 1,500,000,000 | 2,500,000,000 | 400,000,000 |
| 2,500,000,000 | 없음 | 200,000,000 |

- LTV: 40%
- 실제 대출 가능액 = min(구간 한도, 주택가격 × LTV)

### 4.3 거래 부대비용

| 항목 | 값 |
|---|---|
| 중개보수율 (매매 15억 이상) | 0.7% (상한, 협의 가능) |
| 중개보수 부가세 | 10% |
| 취득세 (9억 초과) | 3.0% |
| 지방교육세 | 0.3% |
| 농어촌특별세 (전용 85㎡ 초과) | 0.2% |

매수 부대비용률 = 취득세 + 지방교육세 + (해당 시 농특세) + 중개보수율 × 1.1
- 85㎡ 이하: 4.07%
- 85㎡ 초과: 4.27%

## 5. 계산 로직

### 5.1 양도차익 안분

재건축 조합원 취득이므로 양도차익을 두 덩어리로 나눈다. 관리처분계획인가일을 기준으로 보유기간 기산일이 다르기 때문이다.

```
취득가액합계 = acq_price_prior + contribution

인가전_양도차익 = right_value - acq_price_prior

인가후_양도차익 = sale_price - member_supply_price - necessary_expense

청산금비율 = contribution / member_supply_price

청산금분_양도차익 = 인가후_양도차익 × 청산금비율
기존건물분_양도차익 = 인가전_양도차익 + 인가후_양도차익 × (1 - 청산금비율)

총_양도차익 = 기존건물분_양도차익 + 청산금분_양도차익
```

### 5.2 장기보유특별공제

```
과세비율 = (sale_price - 1,200,000,000) / sale_price
  단, sale_price <= 1,200,000,000 이면 과세비율 = 0 이고 양도세 = 0

과세_기존건물분 = 기존건물분_양도차익 × 과세비율
과세_청산금분   = 청산금분_양도차익 × 과세비율

공제액 = 과세_기존건물분 × (hold_rate_prior + live_rate_prior)
       + 과세_청산금분   × (hold_rate_contrib + live_rate_contrib)
```

### 5.3 세액

```
양도소득금액 = (과세_기존건물분 + 과세_청산금분) - 공제액
과세표준 = 양도소득금액 - 2,500,000
  음수면 0

산출세액 = 과세표준 × 해당구간세율 - 해당구간누진공제
지방소득세 = 산출세액 × 10%
양도세총액 = 산출세액 + 지방소득세
```

### 5.4 매수 상한 — 구간 탐색

**이 부분을 단순 역산으로 구현하면 틀린다.** 매수가가 대출 한도 구간을 결정하고, 대출 한도가 다시 매수 가능가를 결정하는 순환 구조다.

```
매도순현금 = sale_price
           - sale_price × 0.007 × 1.1
           - 양도세총액
           - mortgage_balance

가용자금 = 매도순현금 + cash_on_hand + extra_fund

부대비용률 = area_over_85 ? 0.0427 : 0.0407
```

각 대출 구간 k(하한 Lk, 상한 Uk, 한도 Dk)에 대해:

```
1) 대출가능액 Dk' = min(Dk, 매수가 × 0.40)
   매수가가 미정이므로, 우선 Dk를 쓰고 4)에서 재검증한다.

2) 후보가 Pk = (가용자금 + Dk) / (1 + 부대비용률)

3) 구간 유효성 판정
   - Lk <= Pk < Uk  →  Pk 를 유효 후보로 채택
   - Pk >= Uk       →  Uk 에 클램프. 필요자금 = Uk × (1 + 부대비용률)
                       필요자금 <= 가용자금 + min(Dk, Uk × 0.40) 이면
                       (Uk - 1원) 을 유효 후보로 채택
   - Pk < Lk        →  해당 구간 후보 없음

4) LTV 재검증
   채택된 후보 P 에 대해 실제 대출 = min(Dk, P × 0.40)
   필요자금 = P × (1 + 부대비용률)
   필요자금 <= 가용자금 + 실제대출 이 성립하지 않으면
   성립할 때까지 P 를 낮춘다.

최종 매수상한 = 유효 후보 중 최댓값
```

유효 후보가 하나도 없으면 "매수 불가"를 표시한다. 임의로 근사값을 내지 않는다.

### 5.5 민감도

`extra_fund` 를 0 / 1억 / 2억 / 3억 / 5억 으로 바꿔가며 5.4를 반복 실행하고 결과를 표로 보여준다. 계단 구조 때문에 증가폭이 균등하지 않다는 점이 이 표의 핵심이다.

## 7. 화면 요구사항

- 한 화면에서 입력과 결과를 동시에 본다. 입력값을 바꾸면 즉시 재계산한다.
- 미입력 필수 항목이 있으면 결과 영역에 계산 결과를 표시하지 않고, 어떤 항목이 비었는지 나열한다. 부분 결과나 추정치를 보여주지 않는다.
- 화면 문구에 내부 용어를 노출하지 않는다. 필드명, 테이블명, 함수명, 변수명, 에러코드를 사용자에게 보이는 곳에 쓰지 않는다.
- 결과 하단에 고정 문구를 둔다: 세액은 참고용 추정치이며 확정 세액은 세무 전문가 확인이 필요하다는 취지.

necessary_expense    = 0

hold_rate_contrib    = 0.40

```

기대: 가용자금     ≈ 2,339,800,000
기대: 매수상한     = 2,500,000,000
```

### 케이스 2

```
sale_price = 2,550,000,000
extra_fund = 100,000,000

기대: 매수상한 ≈ 2,536,000,000  (오차 ±500만원)
```

### 케이스 3

```
sale_price = 2,550,000,000
extra_fund = 200,000,000

기대: 매수상한 ≈ 2,633,000,000  (오차 ±500만원)
```

### 케이스 4 — 경계 검증

```
sale_price = 2,550,000,000
extra_fund = 0

2,499,999,999는 가능, 2,500,000,000은 불가로 판정되어야 한다.
(구간 정의가 [하한, 상한)이므로 25.0억은 세 번째 구간 — 대출 한도가 4억에서 2억으로 줄어든다.
 2026-09-07 정정: 최초 문구는 "25.0억은 가능"이었으나 §4.2 구간 정의와 어긋났다)

이 계단 현상이 나타나지 않으면 5.4를 잘못 구현한 것이다.
```

### 케이스 5 — 비과세

```

기대: 양도세총액 = 0
```

테스트 결과를 "0건 실패" 같은 요약으로만 보고하지 않는다. 케이스별로 기대값, 실제값, 차이를 모두 나열한다.

## 9. 금지 사항

1. 4항의 세율과 대출 한도를 코드에 직접 쓰지 않는다. 설정으로 분리하고 시행일을 함께 보관한다.
2. 필수 입력이 비었을 때 0이나 임의 기본값으로 대체하지 않는다. 계산을 중단한다.
3. 양도세 계산이 실패했을 때 양도세를 0으로 두고 순현금을 계산하지 않는다. 실패를 그대로 노출한다.
4. 5.4의 구간 탐색을 단일 나눗셈으로 대체하지 않는다.
5. 미구현 기능을 화면에 비활성 버튼이나 자리표시자로 두지 않는다.
6. 사용자에게 보이는 문구에 내부 용어를 쓰지 않는다.
7. 2항의 제외 항목을 임의로 구현하지 않는다.

## 11. 완료 조건

각 Phase는 아래를 모두 만족해야 완료로 본다.

- 8항 해당 케이스가 실제 실행되어 통과
- 화면에서 입력하고 결과를 확인하는 경로가 실제로 동작 (테스트 코드에서만 호출되는 상태는 미완료)
- 필수 입력을 비운 상태에서 결과가 표시되지 않는 것을 확인
- 9항 금지 사항 위반이 없는지 자체 점검 결과 첨부

### 매도 예상가 — 두 값 병행

| 금액 | 출처 |
| --: | :-- |
| 25.50억 | 네이버 호가 중간값 (실거래 아님) |
| 24.35억 | 최근 3개월 실거래 중위 (84㎡ A~D 타입 합산) |

호가와 실거래는 성격이 다르므로 한쪽으로 덮어쓰지 않는다.
두 값으로 각각 계산해 매도가 1억 차이가 매수 상한을 얼마나 바꾸는지 함께 본다.

이 표는 매 보고서에 상태와 함께 그대로 포함한다.
