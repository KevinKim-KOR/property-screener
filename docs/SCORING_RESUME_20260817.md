비교군을 못 만들면 **제외가 아니라 점수 결측**(`NO_PEER_GROUP`)으로 남긴다.

## B. 남은 문제 — 하나로 수렴한다

```
5㎡ 버킷 17종 중 비교군 20곳을 채우는 것이 2종뿐
  → A80_85 (121곳), A55_60 (60곳) 만 통과
  → 나머지 15종은 구에서도 벨트에서도 20 미달 → 점수 결측
  → 결과: 점수 결측 42.9% (136 / 317)
```

게이트 통과 317건의 평형 분포:

| 평형 | 통과 | 채점 | 평형 | 통과 | 채점 |
| :-- | --: | --: | :-- | --: | --: |
| A80_85 | 121 | 121 | A100_105 | 10 | 0 |
| A55_60 | 60 | 60 | A120_125 | 10 | 0 |
| A70_75 | 18 | 0 | A115_120 | 10 | 0 |
| A110_115 | 15 | 0 | A75_80 | 9 | 0 |
| A130_135 | 11 | 0 | A50_55 | 9 | 0 |
| A105_110 | 11 | 0 | 그 밖 6종 | 33 | 0 |

**이 하나가 아래 셋의 공통 원인이다.**

1. 점수 결측 42.9%
2. 표본 기준 재검토 (적격의 45.5%가 최근 1년 거래 5건 이하)
3. 꼬리 비율의 표본 흔들림 (채점 181건이면 10% 꼬리의 표준편차 약 2.2%p)

폴백은 `법정동 0 / 구 181 / 벨트 0 / 실패 136` 이었다.
**벨트가 0인 것은 구조적이다** — 구에서 20을 못 채우는 평형은 벨트(2개 구)에서도 못 채운다.

## B-2. 표본 부족은 기간 창에서도 같은 모습으로 나타난다 (2026-08-29 추가)

기간 창의 시작일이 코드에 고정 문자열로 박혀 있었다. `base_date` 상대 계산이
아니어서 시간이 갈수록 창이 넓어졌다(2026-08-27 기준 '3개월' 창이 실제 3.9개월,
'12개월' 창이 13.9개월). 아무 신호도 나지 않는 종류였다.
`common/date_window.py` 의 `window_start()` 로 전부 상대 계산으로 바로잡았다.

**바로잡은 뒤 드러난 것**

| 항목 | 고정 창 | 상대 창 |
| :-- | --: | --: |
| 가격 창 3M | 117 | **38** |
| 가격 창 6M | 114 | 170 |
| 가격 창 12M | 229 | 205 |
| 게이트 통과 | 323 | 286 |
| 점수 결측 | 139 | 120 |

3개월 창으로 값이 나오는 단지가 **117곳 → 38곳**으로 줄었다. 이전 117곳 중
상당수는 실제로 3.9개월치였다. 값이 나오는 413곳 중 **205곳(약 절반)이 12개월
창**이며, 화면의 '최근 거래가'가 사실은 1년치 중위값인 경우가 그만큼 많다.

**점수 결측(120곳, 42.0%)과 뿌리가 같아 보인다.** 둘 다 "단지×평형 단위로
거래가 얇다"는 하나의 사실이 다른 방식으로 드러난 것이다.

- 비교군을 20곳 채우지 못한다 → **점수 결측 42.0%**
- 3개월 안에 거래가 3건이 안 된다 → **창을 6개월·12개월로 넓힘**

따라서 §C 의 선택지를 검토할 때 **기간 창도 함께 봐야 한다.** 버킷을 넓히면
(C-1) 비교군뿐 아니라 기간 창도 좁아질 수 있고, 반대로 버킷을 그대로 두면
두 문제가 함께 남는다. 둘을 따로 조정하면 한쪽을 고칠 때 다른 쪽이 나빠질 수 있다.

화면에서는 `가격 기준`(3개월/6개월/12개월)과 `최근거래일` 컬럼으로 확인할 수 있다.
12개월 창은 빨강, 6개월은 주황으로 표시된다.

## C. 재개할 때 검토할 선택지

> 판단은 하지 않았다. 선택지와 대가만 적는다.

### C-1. 버킷을 5㎡ → 10㎡ 로 넓힌다

- **얻는 것**: 버킷 수가 절반으로 줄어 비교군 20곳을 채우는 평형이 늘어난다.
- **치르는 것**: 전고점 오염이 다시 생길 수 있다. 서로 다른 평형의 거래가 한 버킷에 섞이면 큰 평형의 고가 거래가 작은 평형의 전고점이 된다.
- **5㎡ 로 쪼갠 이유**: 발주자 설명으로는 **2026-08-01 래미안원베일리 사례** — 평형이 뭉뚱그려져 전고점이 오염된 건이다.
  ⚠️ **이 사례는 설계 문서에서 찾지 못했다(확인 필요).** `SCORING_DESIGN_v4.2.md` §13.3에 5㎡ 버킷 표기 정밀화 언급은 있으나 도입 경위는 기록돼 있지 않다. 재개 전에 근거를 문서로 남겨두는 편이 좋다.

### C-2. `min_peer_n` 을 20 → 낮춘다

- **얻는 것**: 점수가 나오는 평형이 늘어난다.
- **치르는 것**: 표본이 20 미만이면 중위수와 MAD 가 불안정해 점수가 잡음이 된다. 이번에 20을 유지한 이유가 그것이다.
- 참고: 설정값은 `config/scoring_v3.yaml` 의 `universe.min_peer_n`.

### C-3. 비교군을 평형 무관으로 넓힌다

- **얻는 것**: 비교군이 확실히 채워진다.
- **치르는 것**: 25평과 44평이 같은 비교군에 들어간다. 평단가·하락률의 성격이 달라 비교 자체가 의미를 잃는다.

### C-4. 점수를 계속 만들지 않는다

- **얻는 것**: 현재 상태 유지. 표(하락률·초과하락·전세가율·거래량·M3/M6/M12)는 정상 동작하며 신뢰할 수 있다.
- **치르는 것**: 종합 점수로 순위를 매기는 기능이 없다.

## D. 재개 시 첫 명령

```bash
python -m pc.verification.score_distribution
```

현재 분포와 §19.0 판정이 바로 나온다. **아래 2026-08-17 기준값과 비교하면 그동안 무엇이 달라졌는지 알 수 있다.**

```
■ 점수 분포 판정 · 기준일 2026-08-29

2. 점수가 제대로 퍼져 있나

  중간 점수      46.7점          (정상: 45~55점)   ✓
  90점 이상     19곳 (11.4%)    (정상: 12% 이하)   ✓
  10점 이하     13곳 (7.8%)     (정상: 12% 이하)   ✓

  → 정상입니다

  점수 결측(비교군 부족)  120곳 / 게이트 통과 286곳 (42.0%)
```

> 2026-08-17 기준값은 기간 창이 고정 문자열이던 때의 것이다(중앙값 51.0 /
> 결측 136곳 / 통과 317곳). 창을 상대 계산으로 바로잡으면서 값이 바뀌었으므로
> 위의 2026-08-29 값을 기준으로 비교한다.
>
> 중앙값 허용폭도 50±3 -> **50±5** 로 넓혔다. 붕괴 검출은 V10 과 꼬리 비율
> 검사가 담당하며, 중앙값은 Φ 매핑 특성상 원점수가 치우치면 50 에서 벗어난다.
> 옛 허용폭은 창을 바로잡은 정상 실행(중앙값 46.6)을 반려해, 수정이 화면에
> 반영되지 못하게 만들었다.

**읽는 법**

| 다시 돌렸을 때 | 뜻 | 다음 행동 |
| :-- | :-- | :-- |
| 결측 비율이 뚜렷이 낮아짐 | 실거래가 쌓여 비교군이 채워지는 중 | 구조 변경 없이 기다리는 것도 선택지. C-1~C-3 보류 |
| 결측 비율이 그대로(40%대) | 데이터 증가로는 해결되지 않음 | 버킷·비교군 재설계 필요. C-1~C-3 중 선택 |
| 중앙값이 47~53 밖 | 정규화가 다시 깨짐 | 비교군에 제외 단지가 섞였는지부터 확인(A-5와 같은 증상) |
| 꼬리가 12% 초과 | 계산 붕괴 신호 | V10·V11 이 run 을 실패 처리했는지 확인 |

DB가 비어 있으면 화면에서 [최신 자료 가져오기]를 먼저 눌러야 한다(3~4분).

## E. 화면에 점수 컬럼이 없다

**v4.3 대시보드에는 퀀트점수 표시 컬럼이 아예 없다.** 표시 컬럼 16종(최근 거래가·전고점·전고점 시점·하락률·초과하락·전세가율·M3·M6·M12·거래 건수·거래량비·연식·브랜드·역세권·학원가·학교거리)에 점수가 빠져 있다. `pc/templates/index.html` 의 `OPTIONAL_COLUMNS`.

**API 는 준비되어 있다.** `/api/properties` 가 아래를 반환한다.

| 필드 | 내용 |
| :-- | :-- |
| `market_score` | 점수. 결측이면 `null` (0 이 아니다) |
| `score_missing` | 결측 여부 |
| `score_missing_reason` | `"비교군 부족"` |

재개할 때 컬럼 하나만 추가하면 된다. **결측을 0점으로 표시하지 말 것** — 0으로 채우면 최하위 매물처럼 보인다. 컬럼 추가는 UI 설계 사항이라 임의로 넣지 않았다.
