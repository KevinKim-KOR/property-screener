# 부동산 스크리너 설계서 v4.0

> **버전**: v4.2.0
> **작성일**: 2026-07-31
> **이전 문서**: v3.3은 폐기. 미룬 항목은 전부 §8에 옮겨 적었으므로 따로 볼 필요 없다
> **분량 원칙**: 이 문서는 A4 4장을 넘기지 않는다. 넘으면 범위가 잘못된 것이다

## 0. 왜 범위를 줄였나

v3.3은 팩터 15개, 게이트 20여 개, 화면 3계층을 한 번에 요구했다. 구현 결과 서울 전체 단지가 섞이고, 값이 없는데 문장이 생성되고, 검증 리포트는 전부 "통과"로 나왔다.

**실패 지점이 많으면 조용히 실패한다.** 그래서 다음 원칙으로 다시 시작한다.

| # | 원칙 |
| :-- | :-- |
| 1 | **발주자가 직접 검증할 수 있는 것만 만든다.** 네이버에서 5분 안에 확인 가능해야 한다 |
| 2 | **축을 하나씩 검증한 뒤 합친다.** 이번에는 정렬만 한다. 종합 점수는 §7 참조 |
| 3 | **하나가 확실히 돌아간 뒤 다음을 붙인다** |
| 4 | **안 만드는 것은 §9에 기록한다.** 조용히 빼지 않는다 |

## 3. 계산

단지 × 평형마다 아래 4단계를 계산한다. 기준일은 실행일.

### 3.1 최근 거래가
```
최근거래가 = 최근 3개월 유효거래의 중위값
```
3개월 내 거래가 없으면 → 최근 6개월, 그래도 없으면 → 최근 12개월.
12개월에도 없으면 제외(§4).

### 3.2 전고점
```
기준일부터 60개월 전까지, 3개월 단위로 창을 밀며:
    창 안의 유효거래가 3건 이상이면 → 그 창의 상위 90% 지점 값을 기록
전고점 = 기록된 값들 중 최대값
전고점시점 = 그 창의 마지막 달
```
> 단일 최대값을 쓰지 않는 이유: 이상거래 1건이 전고점이 되는 것을 막는다.
> **시간 감쇠는 적용하지 않는다.** 대신 `전고점시점`을 화면에 표시해 발주자가 직접 판단한다.

#### 왜 창당 3건인가
상위권을 소규모 나홀로 단지가 독식한 원인이 여기 있었다. 창 안에 거래가 1~2건이면 그 값이 곧 전고점이 되어 **하락률이 극단적으로 튀고**, 그 극단값이 분포 전체를 끌어당긴다.

**나홀로 단지를 걸러낸 것은 이 조건이지 12개월 최소 건수가 아니었다.** (§11 참조)

### 3.3 하락률 / 초과하락률
```
하락률     = 1 − 최근거래가 / 전고점

강남권중위 = 같은 평형 전체 단지의 하락률 중위값
초과하락률 = 하락률 − 강남권중위
```
`초과하락률`이 양수면 시장 평균보다 더 떨어진 것이다. **시장 전체가 빠진 부분은 신호가 아니므로 빼낸다.**

### 3.4 거래량비
```
거래량비 = 최근 3개월 거래건수 / (최근 12개월 거래건수 ÷ 4)
```
1.0보다 크면 거래가 평소보다 활발하다.

## 4. 제외 규칙

| 조건 | 화면 표기 |
| :-- | :-- |
| 최근 12개월 3건 미만 **또는** 24개월 8건 미만 | 거래가 드물어 가격을 판단하기 어렵습니다 |
| 직거래·해제 비중 30% 초과 | 직거래·취소 거래가 많아 가격을 믿기 어렵습니다 |
| 전고점을 못 구함 | 과거 거래가 부족해 비교 기준을 잡지 못했습니다 |
| 평형 구분 실패 | (표에서 제외. 사유 표기 없음) |

**제외된 단지는 별도 목록으로 볼 수 있게 한다.** 조용히 사라지면 안 된다.

#### 제외 표기 원칙
`검증 미달`, `부적격` 같은 표현을 쓰지 않는다. **단지에 문제가 있는 것이 아니라 우리가 판단할 자료가 부족한 것이다.**

| 쓰지 않음 | 씀 |
| :-- | :-- |
| 검증 미달 (제외) | 판단 보류 |
| 부적격 매물 | 자료 부족 |
| 시장점수 (호가 대조 전) | (제외 목록에는 점수 관련 표기를 하지 않는다) |

제외 목록의 카드/행에는 **단지명·평형·제외 사유·네이버 링크만** 둔다. 호가·점수·검증 상태 칸을 만들지 않는다.

## 5. 화면

### 5.1 형태 — 표 기본, 카드 선택

**기본은 표다.** 우측 상단에 전환 버튼을 둔다.

```
                                        [ 표 ] [ 카드 ]
```

| | 쓰는 때 | 한 화면 |
| :-- | :-- | :--: |
| **표** (기본) | 전체를 훑고 비교할 때 | 20행 이상 |
| **카드** | 상위 몇 개를 자세히 볼 때 | 6개 |

선택은 브라우저에 기억시킨다. 다시 들어와도 마지막에 본 형태로 뜬다.

**표·카드 어느 쪽에서도 쓰지 않는 것**: 배지, 이모지, 진행 막대, 같은 값의 중복 표시.

### 5.1.1 기존 기능 보존 (⚠️ 회귀 방지)

**재작업 중에 이미 동작하던 기능이 사라졌다.** 금액 슬라이더가 그 예다. 새 기능을 안 만든 것과 있던 것을 없앤 것은 다르다.

착수 전에 **현재 화면에서 동작하는 기능 목록**을 만들고, 작업 후 하나씩 대조한다.

| 기능 | 이전 | 이후 | 비고 |
| :-- | :--: | :--: | :-- |
| 금액 범위 슬라이더 | 있음 | ? | **복구 필요** |
| 평형 필터 | 있음 | ? | 확인 |
| 지역 필터 | 있음 | ? | 확인 |
| 단지명 검색 | 있음 | ? | 확인 |
| 네이버 바로가기 | 있음 | ? | 확인 |

이 표를 §6.2 점검 결과에 포함한다. **의도적으로 없앤 기능은 §9 미구현 목록으로 옮긴다.** 조용히 사라지면 안 된다.

### 5.2 컬럼

| 지역 | 단지명 | 평형 | 최근 거래가 | 전고점 | 전고점 시점 | 하락률 | 초과하락 | 거래 건수 | 거래량비 |
|---|---|---|---|---|---|---|---|---|---|
| 서초구 반포동 | 반포자이 | 34평형 | 38.5억 | 44.2억 | 2024.09 | -12.9% | +5.3%p | 11건 | 1.4배 |
| 강남구 대치동 | 은마 | 34평형 | 26.8억 | 29.4억 | 2024.03 | -8.8% | +1.2%p | 23건 | 0.9배 |

- 기본 정렬: **초과하락률 내림차순**
- 모든 컬럼 정렬 가능
- 필터: 지역(서초/강남), 평형(25/34/44)
- 단지명 검색

### 5.3 표기 규칙

| 규칙 |
| :-- |
| 값이 없으면 **그 줄을 통째로 숨긴다.** 빈칸이나 `-`를 남기지 않는다 |
| **같은 값을 두 번 쓰지 않는다.** `최근 실거래 35.0억`과 `3M 실거래 중위 35.0억원`은 같은 값이다 |

| 하락률·초과하락률은 부호를 값에서만 결정한다. `+-` 같은 표기가 나오면 버그다 |

## 6. 검증

### 6.1 발주자 검증 (최종 판정)
표에서 **아무 행이나 3개**를 골라 네이버 부동산에서 확인한다.

| 확인 항목 | 판정 |
| :-- | :-- |
| 그 단지가 서초구 또는 강남구에 있는가 | 아니면 반려 |
| 그 단지에 그 평형이 실제로 있는가 | 없으면 반려 |
| 최근 거래가가 실제 실거래와 맞는가 | 다르면 반려 |

**리포트를 읽고 판단하지 않는다. 화면을 직접 확인한다.**

### 6.2 개발 담당 자체 점검

실행 시 아래를 **스크립트가 자동 출력**한다. 서술형 문장으로 쓰지 않는다.

#### 결과 표기 — 세 가지만 쓴다

| 표기 | 뜻 |
| :-- | :-- |
| `정상` | 검사했고 문제 없음 |
| `이상 N건` | 검사했고 문제 발견. **목록을 반드시 붙인다** |
| `확인 못 함` | **필요한 데이터가 없어 검사 자체를 못 했음** |

> **`확인 못 함`을 `정상`이나 `0건`으로 쓰지 않는다.**
> 이전 점검에서 세대수 데이터가 없는 상태로 "세대수 50 미만 단지 0건"이 출력되어, 상위권이 전부 소규모 단지인데도 통과로 넘어갔다.
> 검사 항목에 필요한 데이터가 없으면 **`확인 못 함`과 그 사유**를 적는다.

#### 출력 예시

```
■ 점검 · 2026-07-31

대상 구
  11650 서초구   287
  11680 강남구   324
  그 외             0        ← 0이 아니면 실행 중단

표시 / 제외
  표시   431
  제외   181
    거래 부족           98
    직거래·취소 과다     15
    전고점 없음         68

빈칸
  최근 거래가     0
  전고점          0
  거래량비       12

점검 항목
  1. 그 외 지역 혼입          정상
  2. 빈칸에 추정치 삽입        정상
  3. 화면 내부 용어            정상
  4. 거래 부족 단지 노출      정상
  5. 세대수 대비 거래 과다     확인 못 함 (세대수 자료 없음. 9-8 항목)
  6. 호가 대조                 확인 못 함 (호가 자료 없음. 9-17 항목)

  → 이상 0건 / 확인 못 함 2건

정렬 상위 10건
  1. 반포자이      34평형  서초구 반포동  +5.3%p  11건
  2. 은마          34평형  강남구 대치동  +1.2%p  23건
  ...

거래 3~5건 단지 (숫자 신뢰도 낮음)
  1. ...
```

**"정상"만 쓰고 목록을 안 붙이면 그 점검은 무효다.**

### 6.3 통과 판정

```
이상 0건        →  통과
이상 1건 이상    →  불통과.  개별 항목이 통과여도 전체는 불통과
확인 못 함       →  통과에 영향 없음. 단, 사유와 §9 항목 번호를 적는다
```

**이상이 하나라도 있으면 화면을 갱신하지 않는다.** 이전 점검에서 중앙값 이탈이 `[이상]`으로 찍혔는데 전체는 `통과`로 넘어가고 화면이 갱신됐다. 그런 판정은 무효다.

## 7. 종합 점수는 언제 붙이나

**이번에 점수를 만들지 않는 것은 폐기가 아니라 순서다.**

### 7.1 왜 지금은 정렬만 하나
축 하나하나가 맞는지 확인되지 않은 상태에서 합치면, 결과가 틀렸을 때 **어디가 틀렸는지 찾을 수 없다.**

이전 시도에서 99점이 나왔을 때 원인이 정규화인지, 가중치인지, 부호 처리인지, 평형 매핑인지 구분되지 않았다. 실제 원인은 크롤러였다. 축이 하나면 발주자가 네이버에서 직접 대조해 5분 만에 판정할 수 있다.

| v4.1 | + 전세가율, 연식, 브랜드 | 정렬 |
| v4.2 | + 역세권, 초등학교 | 정렬 |
| **v4.3** | 6개 이상 | **가중합 → 비교군 백분위 → 0~100** |

### 7.3 v4.3에서 붙일 점수의 형태
```
1) 축별로 비교군 내 상대 위치를 구한다 (중위수·MAD 기준)
2) 축을 성격별로 묶고 묶음마다 가중치를 준다
3) 묶음을 합친 뒤 정규분포 누적분포로 0~100에 매핑한다
   → 중앙값 50, 상위 10%가 대략 63점
```
**상한 100으로 자르지 않는다.** 자르는 순간 상위권 내부의 순서가 사라진다.

각 축이 이미 검증을 통과한 상태이므로, 점수가 이상하면 **합치는 로직만 의심하면 된다.**

### 7.4 앞당기지 않는다
축이 6개 미만인 상태에서 점수를 만들자는 요청이 오더라도 거절한다. 가중치를 정할 근거가 없기 때문이다.

## 8. 완료 판정

```
1. 그 외 지역 건수 = 0
2. 빈칸 자리에 추정치가 들어가지 않았음
3. 화면에 내부 용어 0건
4. 상위 10건 목록 + 거래 3~5건 단지 목록 출력

```

## 11. 이번 조정의 배경 (2026-07-31)

이전 산출 결과에서 상위 10건이 아래와 같이 나왔다.

```
한티(933-0) · 동민맥스빌B동 · 이니그마빌-III · 도곡하이빌 · 원팰리스
비젼(102) · 파크힐 · 한티(933-35) · 대치하나빌 · 에벤에셀빌라트
```

강남 대표 단지가 하나도 없고 전부 소규모 나홀로 단지였다. 점수 중앙값도 46.65로 기준을 벗어났다.

**원인은 같다.** 거래가 3~4건뿐인 단지는 중위값과 전고점이 한두 건으로 결정되어 하락률이 극단적으로 튀고, 그 극단값이 분포 전체를 끌어당긴다. 최소 거래 건수 3건이 너무 낮았다.

### 11.1 1차 조정 (v4.1) 과 그 부작용

| 조정 | 이전 | v4.1 |
| :-- | :--: | :--: |
| 12개월 최소 거래 | 3건 | 5건 |
| 전고점 창 최소 거래 | 2건 | 3건 |

**상위권은 정상화됐다.** 디에이치반포라클라스·반포센트럴자이·메이플자이·대치아이파크 등 실제 주요 단지가 올라왔다.

**그러나 제외가 1,329건으로 늘었다.** 전체 2,246건의 절반이 넘는다. `래미안서초6차 44평형`, `서초2차e-편한세상 44평형` 같은 정상 단지가 대량 탈락했다.

### 11.2 2차 조정 (v4.2) — 방향 정정

**올려야 했던 것은 건수가 아니라 기간이었다.** 부동산은 거래 빈도가 극도로 낮아 12개월 창에서 건수를 올리면 정상 단지까지 잘린다. 특히 44평형 이상은 원래 거래가 드물다.

| 조정 | v4.1 | **v4.2** |
| :-- | :--: | :--: |
| 12개월 최소 거래 | 5건 | **3건** (원복) |
| 24개월 누적 최소 | — | **8건** (신규) |
| 전고점 창 최소 거래 | 3건 | **3건** (유지) |

나홀로 단지를 걸러낸 것은 **전고점 창 3건**이었다. 12개월 5건은 부작용만 냈다.

## 13. v4.3 변경 사항 (2026-08-02)

### 13.1 전고점 및 가격 역전 게이트 정교화
* **전고점 산출 기준 상향 (`p90` → `p95`)**: 최근 60개월 유효거래 전체의 상위 95% 지점(p95)으로 전고점을 설정하여 고점 근처 단지들의 과도한 제외를 방지.
* **역전 게이트(`G3_INVERTED_PRICE`) 완화**:
  * `최근가 > 전고점 × 1.10` 초과 시에만 제외.
  * 그 미만(`전고점 <= 최근가 <= 전고점 × 1.10`)은 **적격(PASS)** 판정 및 하락률 **0.0% (`🔥신고가`)** 표시.

### 13.2 모멘텀 지표 최소 거래 조건 완화
* M3, M6, M12 지표 계산 시 각 구간 및 이전 구간 최소 요구 거래 건수를 **3건 → 2건**으로 완화하여 강남권 대형·핵심 단지들의 모멘텀 산출률을 향상.

### 13.3 화면 평형 버킷 전용면적 표시 정밀화
* `translate_area_type`: 내부 5㎡ 단위 버킷(`A50_55`, `A70_75`, `A75_80` 등)을 하드코딩된 평형(59㎡, 84㎡, 114㎡)이 아닌 **실제 버킷 전용면적(53㎡, 74㎡, 77㎡ 등)**으로 정확하게 표기 (`34평형 · 전용 77㎡` 등).
